# AI 视听制作实战错误复盘与避坑库（V2.0 重构版）

> **使用方式**：每条错误均标注**生命周期状态**与**适用模型边界**，避免旧模型补丁永久固化或误伤新模型能力。  
> **状态标签**：
> - `CORE-PERMANENT`：底层视听/物理/制片规律，跨模型永久生效；
> - `UPGRADED-IN-V2`：第一部剧暴露出的双刃剑问题，已在 V2.0 从架构根源升级解决；
> - `MODEL-BOUND`：与特定模型版本强相关的限制，随适配器分流管理。

## 二、典型高危错因拆解（核心细节速查）

### `ERR-002`｜纯白平光参考图稀释暗调光比 + 平静头肩照引发“肌肉锁死”
- **现象**：绑定纯白 `#FFFFFF` 平光人物图与平静面部特写后，角色喊叫声嘶力竭但面部无泪僵平，暗调电影光被整体洗灰成电视剧平光；挂载无需露脸的背景人物图还会逼迫模型强行拉远景别。
- **根因**：多模态视觉编码器会继承参考图的光比与表情权重；无关参考图会倒逼模型把它塞进构图里。
- **V2.0 铁律**：① 进视频的 `CHAR-VID` 统一用中灰底 `#555A64` + 45° 定向侧光；② 强爆发戏严禁挂载平静头肩照，改用 S 级情绪剧照首帧驱动；③ 画面不露脸的角色严禁挂参考图、严禁在 Prompt 提其名字。

### `ERR-007`｜多人全景喂三视图触发人物克隆
- **现象**：多人餐桌戏喂入含 3 个同款形象的三视图，AI 自动复制分身把 6 人画成 7 人，且配角静止如蜡像。
- **V2.0 铁律**：三视图只做 `CHAR-BASE` 母档；**凡 2 人以上视频任务一律喂单人单视角图（`CHAR-VID`）**，并在正文明确硬人数上限（如“画面中严格共计 6 人”）+ 给配角写入具体反应微动。

### `ERR-008`｜劈开完整情绪原子 + 虚构前景肩导致冷启动断层
- **现象**：将同一空间内一口气爆发的“吼叫 → 甩围裙离席”硬拆成两条视频，且特写强行虚构了贴近镜头的前景肩，拼在一起后距离突变且动作冷重启。
- **V2.0 铁律**：同空间连贯情绪爆发打包进一条连续视频；开拍前确认全景真实距离（相距 2.5 米绝不在特写硬塞前景肩）；相邻两段在前段结尾预埋 20%–30% 起势、后段第 0 秒直接进动态。

### `ERR-011`｜极端动态截帧喂给同机位视频触发“姿态粘滞冻僵”
- **现象**：截取双手悬空、张大嘴的动态帧作为参考图去续拍同机位下一段，导致人物双手悬空定格 2–4 秒不动。
- **V2.0 铁律**：截帧反锁只选**自然放松静态帧**（手稳放桌面/方向盘、闭嘴正常坐姿）；带人物截帧优先用于切换新机位时的服装光色参考，同机位续拍回退到纯净空景 + 单人图。

### `ERR-012`｜车内多窗 90° 透视强转致挡风玻璃融化
- **现象**：喂正向前视车厢图却要求向左看敞开车门外，导致前挡风玻璃扭曲融化成侧门洞、人物瞬移到车头。
- **V2.0 铁律**：车内外参考图物理隔离，严禁混挂；优先采用**车外左侧平视 + 车门外 3/4 朝内 85mm 近景**避开 90° 拐角；非开关门镜写死车门全程保持敞开静止与 A 柱/车框刚体不变形；复杂车内机位强制先在 `Seedream 5.5` 出同角度 S 级首帧。

### `ERR-015`｜风格锚与空景重复挂载，且没交代空景与人物、机位的关系
- **状态 / 适用范围**：`CORE-PERMANENT`
- **具体案例**：mama-birthday / 第一幕 / `U01B`。同时绑定 `@风格光影锚_餐厅夜` 和 `@餐厅夜景空景`（后者本来就是参考前者生成的），正文又写成“延续 A 与 B 的左侧墙面”，结果光影描述重复，父亲坐在空景哪个位置、机位从哪边拍都没写，用户实测出片效果差。
- **第一性原理根因**：同源参考图重复挂载会稀释权重、挤占名额；空景只被当成“背景贴图”，模型拿不到人物位置、机位方向和近景下背景该露哪一块。
- **即时急救与永久预防**：已绑定空景或首帧的单元删掉风格锚（`lint_prompt.py` 自动机械拦截 `RL-18`）；高稳定性默认走 S 级首帧驱动，极少数 A 级必须写明“人物位置 + 朝向 + 机位方向 + 背景露哪一块 + 不复刻全景构图”。

### `ERR-016`｜核心连戏道具无统一视觉锚点 + 参考图与场景状态自相矛盾
- **状态 / 适用范围**：`CORE-PERMANENT`
- **具体案例**：mama-birthday / 第一幕 / `U02A` 与 `U04 镜2`。① `U01A` 35mm 近景凭空画清了一盘清蒸鱼，紧接着的 `U02A`（端鱼放餐边柜）只挂空景和人物图、无鱼近景锚点，导致相邻两镜鱼盘不一致；② `U04 镜2` 俯拍要求“桌中央鱼盘位留空”，却继续绑定桌中央还摆着鱼的 `S0` 旧空景，图与文字直接打架。
- **第一性原理根因**：资产体系只建模了“人/景”，漏了“核心道具”和“世界状态变更”；站 3 孤立看单镜凑图，站 4 只查多余绑定不查缺失与状态冲突。
- **即时急救与永久预防**：凡跨 ≥2 镜近景核心道具必须先建中灰底 `PROP` 定妆锚并让所有相关首帧统一溯源（`RL-16`）；场景发生状态变更（`S0 → S1`）后，所有下游镜必须切到 `S1` 状态图/首帧，严禁喂 `S0` 旧空景（`RL-17`）。

### `ERR-017`｜后场重要角色与房间门洞未前置定型，导致下游倒逼上游或空间打架
- **状态 / 适用范围**：`CORE-PERMANENT`
- **具体案例**：mama-birthday / 第一幕 / `U02B`、`U03B`。为省前期几张图，未先定型妈妈与爷爷的角色图，直接在 `U03B`（背影）和 `U02B`（全景）里靠文字盲抽，导致后续幕次建正脸母档必须反过来迁就；且空景右后墙只有餐边柜、未规划厨房门洞钟面方位，导致 `U03B` 凭空多出一扇门。
- **第一性原理根因**：过度担忧静态图成本（实际上 1 次视频返工成本 ≈ 10+ 张图），且缺少 360° 房间钟面拓扑约束。
- **即时急救与永久预防**：分镜阶段强制画清 360° 房间钟面拓扑；凡全剧后场有重要正脸戏份的角色均在首次入画（含背影/远景）前先出 `CHAR-BASE`/`CHAR-VID`（在 `Seedream 5.5` 生背影首帧时直接喂 `CHAR-BASE` 三视图锁背影，绝不喂进视频）。

### `ERR-018`｜局部修改资产或提示词后未做全局遍历同步，导致“顾头不顾尾”
- **状态 / 适用范围**：`CORE-PERMANENT`
- **具体案例**：mama-birthday / 第一幕 / `U02B-1`。首帧选定“改法 2（局部重绘补入 4 位虚化长辈，避免对着空椅子喊）”后，若仅修改生图提示词而未同步修改下游 `U02B-1` 视频提示词、《视觉圣经》和实测台账，会导致视频仍写“画面仅1人”或遗漏长辈停筷反应，图与视频直接打架。
- **第一性原理根因**：AI 制片是强耦合链路（`分镜 → 圣经 → 首帧 → 本镜视频 → 下游派生首帧/相邻镜`），单点修改必然沿依赖链产生涟漪效应。
- **即时急救与永久预防**：资产或 Prompt 产出后，**每次改动任何内容，必须执行全局影响遍历检查**（`RL-19`），逐一核对上游圣经/分镜包、本镜生图与视频 Prompt、下游派生首帧、相邻镜头衔接与实测台账，确认全链路自洽后再执行生成。

### `ERR-019`｜全量硬套首帧锁死动态演技 + 拿 `S0` 旧图靠文字硬擦 + 单图过载多人座位
- **状态 / 适用范围**：`CORE-PERMANENT`
- **具体案例**：mama-birthday / 第一幕全体首帧与 `U02B-1`。① 全幕 12 镜全部做静态首帧导致近景对白/哭戏第 0 帧面部肌肉与嘴型被焊死，视频表现力平木；② 一直挂含鱼且空椅的 `S0` 全景空景 `SCENE-DINING-NIGHT`，却靠文字要求“无鱼+坐4人”，参考图像素权重压过否定文字，导致反复错位；③ `U02B-1` 硬塞 5 人精确座位 + 9 菜 + 留空鱼位，反复抽不出满意首帧。
- **第一性原理根因**：静态首帧擅长锁空间与道具，却天然压制动态微表情；多模态模型中参考图像素远强于文字否定词，且单图无法充当 3D 引擎。
- **即时急救与永久预防**：实施**结构/表演双轨分流**——仅在俯拍/框中框/核心道具/手部特写/走位镜（30%–40%）做 S 级首帧；全部人物近景/对白/情绪爆发镜（60%–70%）取消首帧、改用 `CHAR-VID + 干声` 直出（文字锁单墙/虚化夜窗，不挂全景空景）；需要 `S1` 无鱼桌面时直接用 `S0` 局部编辑生成 `@餐厅夜景_S1无鱼`；多人群戏做减法改用中近景+虚化单一肩背前景与左右眼神对切。

### `ERR-020`｜场景状态变更只写“原位消失”却漏写“道具去向”，违背物理守恒
- **状态 / 适用范围**：`CORE-PERMANENT`
- **具体案例**：mama-birthday / 第一幕 / `3b. @餐厅夜景_S1无鱼`。剧情在 `U02A` 已交代小屿将桌中央清蒸鱼端放至 `1–2 点` 餐边柜苹果盘旁，但编写 `3b` 局部编辑 Prompt 时只写了“移除桌中央鱼盘”，遗漏了在同画面的 `1–2 点` 餐边柜台面上补放这盘鱼，导致鱼盘凭空蒸发、后续入画空间穿帮。
- **第一性原理根因**：状态迁移缺少**场记级物质守恒模型（State Diff：`Origin -` 与 `Destination +` 成对绑定）**，导致思考停留在“桌中无鱼”单边标签。
- **即时急救与永久预防**：引入 **`RL-20` 道具物理守恒与成对状态变更门禁**——① 站 1 写 `S0 → S1` 时必须用成对格式写出 **`Origin -`（原位消失）与 `Destination +`（新落点出现/移出房间）**；② 站 2 局部编辑 `S1` 空景时同时上传 `S0` 空景 + `PROP` 道具图，**同步执行原位移除与新位补放**；③ 站 4 独立审查必须按 `State Diff` 核对每张 `S1` 图与后续拍到新落点的镜头。
